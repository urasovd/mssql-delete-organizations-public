# Разбор прогонов

Группа компаний ведёт учёт в двух базах: БИТ на основе Бухгалтерии
предприятия 3.0 (65 организаций) и ЗУП 3 (22 организации). Одну организацию с
арендным бизнесом нужно передать в отдельные базы: бухгалтерскую и кадровую.
Ниже — цифры прогонов без названий и идентификаторов.

## БИТ: удаление

Четыре прогона на копиях. Первые два — подбор политик, третий — первый на
едином движке, четвёртый — повтор на свежих данных без изменения правил.

| Стадия | Прогон 4 |
|---|---|
| `Prepare` | помечены 63 организации из 64 чужих (одна уже была помечена) |
| `DryRun` | `gate=PASS`; KEEP 52 320, DELETE 1 359 942 + 37 каскадом; 657 строк правил границы; граница `PASS_SIMULATED` |
| `Apply` | бэкап 61 ГБ; `42` — 657 строк; `11` — 41,8 млн строк, граница `PASS`; повторный холостой прогон — 0; снимок −41 808 799 (= `11` + 555 строк `CLEAR_ROW`) |
| `Verify` | `gate=PASS`, DELETE 0; сверка `45`: 798 таблиц, 305 244 строки, 105 счетов, 0 расхождений |
| Время удаления | `11` в прогоне 3 — 54 мин на 41,7 млн строк |

В базе было 58,1 млн строк, осталось 16,4 млн.

### Шаги в 1С

| Шаг | Результат |
|---|---|
| Обновление ИБ | успешно; сначала мешали три открытых клиента другой базы (общая лицензия разработчика) |
| ТиИ `46 -Profile CheckAndTotals` | 2 861 находка, из-за удаления 0; итоги −4,9 млн строк в 83 таблицах за 11,5 с |
| `49` после ТиИ | 3,0 млн строк в итогах трёх регистров, которые ТиИ пропускает |
| `47` | итоги трёх регистров пересчитаны; доступ — 5 шагов; `49` после — 0 строк в 363 таблицах |
| `Files` | 13 590 файлов с томов загружены в базу за 65 мин; 2 файла отсутствовали в хранилище |
| `Compact` | `BinaryData` 1 089 993 → 42 737 строк, 22 мин, `.dt` 8,2 ГБ; файл данных 18,6 ГБ |

### Найденный дефект

Повторный `Verify` после загрузки файлов дал `FAIL` в трёх регистрах
бюджетирования и отчётности. Обработка записывала элемент присоединённого
файла обычной записью, и это запускало логику конфигурации: за минуту записи
файлов отчётов 1С создала и провела 12 документов трансляции в бюджетирование.
Исправление — запись с `ОбменДанными.Загрузка = Истина`. Вывод: любая запись
в базу после удаления — тоже повод для сверки.

## ЗУП: удаление

| Стадия | Прогон 4 |
|---|---|
| `Prepare` | помечена 21 организация |
| `DryRun` | `gate=PASS`; KEEP 6 453, DELETE 30 240; 12 строк правил; `11` — 2 035 516 строк |
| `Apply` | `11` — 2 035 516 строк, граница `PASS`; повторный холостой — 0; ни одна таблица не выросла |
| `Verify` | битых ссылок 0; сверка `45` по всем периодам — `PASS`, 443 таблицы, 103 490 строк |
| Обновление ИБ | 41 обработчик, успешно |
| ТиИ | проверка 58 с: 5 находок, все исходные; пересчёт итогов 6 с |
| `Compact` | 9,3 мин, `.dt` 1,0 ГБ; файл данных 8,2 → 2,7 ГБ |

Повторный `Verify` нашёл 3 объекта в DELETE: два служебных пользователя и
группу доступа, которые 1С создала сама после удаления. Это не остаток
удаления.

После `Compact` сверка сначала дала ложный `FAIL`: загрузка `.dt` заменяет
часть значений «Хранилище значения» заголовком со ссылкой на `BinaryData`, а
`45` сравнивал байты колонки. Теперь такие значения сравниваются по
содержимому; проверено подменой одного байта.

## Превращение в БП КОРП

Копия БИТ после выделения превращена в типовую «Бухгалтерию предприятия
КОРП» 3.0.210.8 ([шаг](CONVERT-TO-TYPICAL.md)). Релиз типовой новее основы
БИТ, обновление прошло вместе с превращением.

| Что | Результат |
|---|---|
| `Postings` | 34 документа БИТ с проводками → «Операции (бух)», 152 проводки, 1 мин |
| `Registers` | 32 516 записей регистров сведений со значениями, которых нет в типовой |
| `Convert` | удаление расширений, загрузка cf, реструктуризация 35 мин |
| Таблиц в базе | 17 770 → 11 707 |
| ОСВ по счетам | 103 счёта, 0 расхождений на каждом этапе |
| ОСВ со всеми субконто | 7 774 строки, 0 расхождений |
| Всего | около часа без неудачных попыток |

Реструктуризация трижды откатывалась с ошибкой «записи регистра сведений
стали неуникальными»: измерение становилось пустым у объекта БИТ без типа в
cf, у значения перечисления БИТ и у служебного `НеудаленныеОбъекты`. После
каждой остановки в скрипт добавлялась подготовка; четвёртая попытка прошла.

Что не переносится и было вынесено на решение бухгалтерам:
- 5 028 документов БИТ без проводок (заявки, реестры платежей, аренда) и
  1 103 присоединённых файла объектов БИТ (1,9 ГБ);
- движения типового документа в регистрах, которых нет в его движениях в
  типовом cf: у 24 ОС, принятых к учёту доработанным документом, пропали
  первоначальные сведения и параметры амортизации. Все они уже сняты с учёта,
  остатки не затронуты;
- регистр с другим идентификатором метаданных при том же имени
  (`СтавкаРефинансированияЦБ`): платформа создала его заново пустым.

## Бизнес-проверка

Перед выдачей пользователи проверяют базу по чек-листу. Для арендного
бизнеса он был таким:

- [ ] действующие договоры аренды: объекты, арендаторы, лицевые счета,
      условия и графики;
- [ ] расчёт арендной платы за текущий период и сравнение с последним
      расчётом до удаления;
- [ ] акты и счета арендаторам;
- [ ] новый договор на тестовом объекте: нужные виды начислений и
      показатели доступны;
- [ ] восстановление последовательности взаиморасчётов с арендаторами;
- [ ] файлы, которых не было в хранилище, прикреплены заново;
- [ ] оборотно-сальдовая ведомость глазами бухгалтера, проведение
      нескольких документов, основные отчёты;
- [ ] маршруты согласования: у ЦФО очищены руководители удалённых
      организаций, заявки проходят маршрут;
- [ ] лишние учётные записи ИБ удалены, регламентные задания включены,
      администратор с паролем.

## Что получилось

- Выделение БИТ целиком, от восстановления копии до `Compact`, — около дня
  работы, из них удаление в SQL меньше часа; самое долгое — загрузка файлов и
  шаги в 1С.
- Политики, набранные на БИТ, ЗУП приняла без изменений, кроме своих
  классификаторов. Повторные прогоны новых вопросов не задавали.
- Самые полезные проверки — повторный холостой прогон, сверка `45` и
  повторный `Verify` после каждого шага, который пишет в базу.
