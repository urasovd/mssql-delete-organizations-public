# ЗУП 3

Копия базы кадрового учёта той же группы компаний: 22 организации, SQL Server
2014, платформа 8.3.27. Выделялась та же организация, что и в БИТ.

| Что | Значение |
|---|---|
| `Справочник.Организации` | **кода нет** — организация задаётся ссылкой |
| Регистры расчёта | `Начисления`, `Удержания`, фактический период действия начислений (`_CRgActP*`); перерасчётов и базового периода нет |
| Планы видов расчёта | `Начисления`, `Удержания` с базовыми, ведущими и вытесняющими видами |
| Регистров бухгалтерии | нет |
| Объём | 4,2 млн строк, 22 организации, 387 сотрудников |
| Права БСП | стандартный режим ограничения доступа (не универсальный) |

Пример настроек — [`example.settings.json`](example.settings.json), решения по
объектам — [DECISIONS.md](DECISIONS.md), цифры прогонов —
[разбор прогонов](../../docs/CASE-STUDY.md).

## Особенности

- **Регистры расчёта** удаляются вместе с регистраторами. Регистраторов с
  движениями и сохраняемой, и чужой организации не было. Период действия
  (`CRgActP`) не содержит организации; сверка `45` сравнивает его через
  движения регистратора, как субконто в БИТ.
- **ПВР** не входят в `COMPLEMENT` и остаются целиком, в том числе виды,
  которыми пользовались только другие организации.
- **Показатели расчёта зарплаты** нужны формулам начислений, поэтому
  защищены.
- **Имена метаданных.** Заголовок имени объекта бывает `{0,0,<id>},"Имя"`.
  Разборщик, понимавший только `{1,0,…}`, не видел 71 тип: документы и
  справочники нельзя было защитить. Исправлено в `scripts/sqlclr/OneC.SqlClr.cs`.
- **Присоединённые файлы** ссылаются на владельца, а не наоборот, поэтому
  нужна роль `KEEP_WITH`. Без неё удалялись бы 560 файлов документов и физлиц
  сохраняемой организации.
- **Обновление ИБ.** Пока ИБ не открыли в режиме обновления, в неё нельзя было
  добавить пользователя.
- **`MCP_Toolkit`** у нового пользователя отвечает текстом, а не JSON. `47`
  сам сериализует ответ в 1С и от этой настройки не зависит.
- **Модель восстановления.** Копия, восстановленная в `FULL`, при сжатии не
  отдаёт журнал (вырос до 13 ГБ). Стадия `Compact` переводит копию в
  `SIMPLE`.
- **Итоги**: 74 регистра накопления, пересчёт за 5 с.
