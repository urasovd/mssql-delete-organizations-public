# Конфигурации

Движок (`scripts/`) и решения по объектам (`policies/`) общие. Здесь лежит то,
что относится к конкретной конфигурации и конкретному выделению:

| Файл | Что это |
|---|---|
| `<конфигурация>/README.md` | особенности конфигурации и хранения, известные ограничения |
| `<конфигурация>/DECISIONS.md` | вопросы, которые возникли на прогонах, и принятые ответы со ссылкой на строку политики |
| `<конфигурация>/<выделение>.settings.json` | настройки прогона для `scripts/Invoke-Extraction.ps1` |
| `<конфигурация>/<выделение>.catalogs.csv`, `.boundary-rules.csv` | слой решений этого выделения поверх общих политик (если нужен) |
| `<конфигурация>/reports/<дата>/` | ваши отчёты прогонов |

Здесь есть:

- [`bit-bp`](bit-bp/README.md) — БИТ на базе Бухгалтерии предприятия 3.0;
- [`zup`](zup/README.md) — ЗУП 3.

Названия организаций, номера документов и пути из прогонов в этих файлах
заменены описаниями: выделялась одна организация из группы компаний.

## Настройки прогона

```json
{
  "server": "sqlserver",
  "database": "zup_copy",
  "source_database": "zup_source",
  "organizations": ["e1cib/data/Справочник.Организации?ref=aabbccddeeff00112233445566778899"],
  "catalog_profile": "aggressive",
  "policy_layers": { "catalogs": [], "boundary_rules": [] },
  "reconcile_period_to": "2026-09-30",
  "backup_directory": "D:\\Backup",
  "infobase": "server1c\\zup_copy",
  "artifacts": "artifacts/zup-example"
}
```

| Поле | Значение |
|---|---|
| `server`, `database` | SQL Server и база, которую режем (копия) |
| `organizations` | сохраняемые организации, одна или несколько, по ссылке |
| `catalog_profile` | `base` или `aggressive` — файл `policies/catalogs-<профиль>.csv` |
| `policy_layers` | необязательно: слои решений прогона, пути от файла настроек |
| `source_database` | необязательно: копия до удаления для сверки `45` |
| `reconcile_period_to` | необязательно: последняя дата сверки, по умолчанию все периоды |
| `backup_directory` | куда `Apply` пишет бэкап перед удалением |
| `infobase` | `Сервер\База` кластера 1С для команд ТиИ |
| `artifacts` | куда писать результаты (от корня репозитория; в Git не попадает) |

### Как задать организацию

Ссылка — это `_IDRRef` организации в любой из форм:
- навигационная ссылка 1С: «Ещё → Получить ссылку» в карточке организации,
  `e1cib/data/Справочник.Организации?ref=aabbccdd…`;
- `УникальныйИдентификатор()` в виде GUID: `66778899-4455-2233-aabb-ccddeeff0011`;
- двоичное значение из SQL: `0xAABBCCDDEEFF00112233445566778899`.

Это одна и та же ссылка: GUID хранит те же 16 байт в другом порядке.

Код у организации есть не во всех конфигурациях (в ЗУП его нет), ссылка есть
всегда. У синхронизированных баз (БП и ЗУП одной группы) она обычно одна и та
же. Скрипты принимают и `-OrganizationCode`.

## Новая конфигурация

1. Создать папку, `README.md` с тем, что известно о конфигурации, и файл настроек.
2. `Invoke-Extraction -Stage Prepare` и `-Stage DryRun`.
3. Каждый `BLOCK` и каждое сомнение по объекту — вопрос в `DECISIONS.md` и
   ответ строкой политики. Если ответ верен везде — в `policies/`, если только
   для этого выделения — в слой прогона.
4. Отчёт прогона — в `reports/<дата>/`.
