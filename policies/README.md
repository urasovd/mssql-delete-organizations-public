# Политики: решения по объектам

Здесь хранится всё, что решено про объекты 1С: что удалять, что защищать, как
разрешать ссылки на границе. Решения пишутся логическими именами 1С (`Справочник.Х`,
реквизит, табличная часть), без `_Fld`, номеров таблиц и ID. Поэтому одна и та же
строка работает в любой базе, где есть такой объект. Физические имена вычисляет
каталог `scripts/40` на каждом прогоне.

Файлы общие для всех конфигураций. Объект, которого в конфигурации нет
(`бит_*` в ЗУП), пропускается, а `41` перечисляет такие объекты в
`skipped_policy_objects` в `summary.json`.

| Файл | Что задаёт |
|---|---|
| `catalogs-aggressive.csv` | профиль «максимум»: из справочников, ПВХ, планов обмена, БП и задач удаляется всё вне KEEP, кроме защищённого слоя |
| `catalogs-base.csv` | осторожный профиль: удаляются только перечисленные бизнес-справочники |
| `boundary-rules.csv` | ссылки остающихся строк на удаляемое: `CLEAR_FIELD`, `CLEAR_ROW` |
| `reconcile-exceptions.csv` | ожидаемые расхождения сверки `45` |

Колонка `source` показывает, где решение принято: `common` — в обеих
конфигурациях одинаково, `bit-bp` или `zup` — на этой конфигурации; для
остальных оно действует так же. Колонки `decided` и `reason` — дата и причина,
чтобы при повторе было понятно, что именно решено и почему.

## Слои

Решения бывают разные для разных выделений: например, наборы доп. реквизитов
в БИТ для одного выделения решили не защищать, а в ЗУП без них не добавлялся
пользователь. Поэтому `41` принимает несколько файлов (`-CatalogPolicyPath`,
`-BoundaryRulesPath`):

1. общий файл из `policies/`;
2. слои прогона из `configurations/<конфигурация>/`, перечисленные в
   `policy_layers` файла настроек.

Строка следующего слоя заменяет строки предыдущих по тому же ключу:
- справочники — `object`;
- правила границы — `object` + `table_part` + `field`.

Роль или действие `NONE` убирает строку совсем. Хэши всех слоёв записываются
в `summary.json` (`catalog_policy_layers`, `boundary_rule_layers`).

Правило для нового решения:
- если оно верно везде, его место в общем файле;
- в слой прогона — только то, что относится к конкретному выделению.

## Справочники (`catalogs-*.csv`)

Колонки: `object;role;condition;source;decided;reason`.

| Роль | Что делает |
|---|---|
| `COMPLEMENT` | из объекта удаляется всё, что не вошло в KEEP (кроме предопределённого). `Справочник.*` — шаблон по имени |
| `PROTECT` | объект не удаляется и не уходит каскадом; системный, регламентный и служебный слой |
| `KEEP_ROOT` | все элементы остаются и сами становятся корнями KEEP: всё, на что они ссылаются, тоже остаётся. `condition` вида `Реквизит<>0` — только строки с заполненным реквизитом |
| `KEEP_WITH` | объект или строка регистра остаётся вместе с объектом, на который указывает реквизит из `condition` (присоединённые файлы — `ВладелецФайла`, `ХранилищеФайлов` — `Файл`). Нужна, потому что ссылка идёт от файла к владельцу и замыкание вперёд её не видит |

`KEEP_ROOT` и `PROTECT` сильнее `COMPLEMENT`.

## Правила границы (`boundary-rules.csv`)

Колонки: `object;table_part;field;condition;target;action;release;source;decided;reason`.

- `object` — объект, которому принадлежит остающаяся строка;
- `table_part` — табличная часть, `*` — любая; пусто для шапки и регистра;
- `field` — реквизит со ссылкой;
- `condition` — дополнительное условие на строку (`Реквизит=Значение`), пусто — без условия;
- `target` — тип удаляемого объекта, `*` — любой;
- `action`:
  - `CLEAR_ROW` — удалить строку табличной части или регистра, владелец остаётся;
  - `CLEAR_FIELD` — очистить поле, строка остаётся;
- `release=yes` — ссылка не удерживает цель в KEEP: человек, которого держит
  только поле «Руководитель», удаляется, поле очищается. Пусто — ссылка
  удерживает цель как обычно, а правило разрешает только ссылки на объекты,
  которые удаляются по другим причинам.

Ссылка, не покрытая правилом, даёт `gate=BLOCK` в `41` и выносится на решение
человека: `boundary-references.csv`, `cascade-blocked.csv`,
`clear-row-candidates.csv`. Новое решение — новая строка политики, а не правка
манифеста.

## Сверка (`reconcile-exceptions.csv`)

Колонки: `register;kind;source;decided;reason`. Регистр из списка при расхождении получает
`EXPECTED` вместо `FAIL`. `kind`:
- `rule` — эффект правила границы;
- `runtime` — данные, которые 1С перезаписывает при работе.
